# 制約・前提（決定事項）

> 移行元: `.kiro/specs/agent-guard/requirements.md`（Kiro spec）。内容は原文のまま章単位で分割している。
> Requirement 番号は全要件を通した通し番号で、他ファイルの要件も「Requirement N」で参照する（1〜19・24・25 は機能要件、20〜23・26 は非機能要件）。

## 決定事項と前提（ユーザーレビュー対象）

依頼書の【要確認】および「要件フェーズで詰めたい論点」について、以下を推奨デフォルトとして採用する。変更する場合は該当要件を修正する。

| ID | 論点 | 決定（推奨デフォルト） | 理由 |
|----|------|------------------------|------|
| D-1 | Web UI を MVP に含めるか | 含める。ただし「CLI が出力した JSON レポートを読み込むだけの、ローカル起動・読み取り専用ビューア」に限定し、MVP の最終マイルストーンとする（CLI / JSON / SARIF を先行リリース可能） | CI 連携の価値は CLI 単体で成立する。ビューアを読み取り専用にすることでスキャン実行 API・認証・ファイルアクセスの攻撃面を持たない |
| D-2 | ユーザーレベル設定（`~/.kiro`, `~/.claude`）をデフォルトでスキャンするか | デフォルトでは対象外。`--include-user-config` 指定時のみスキャンする | CI 環境で無関係なホーム設定を拾う誤検出と、個人設定の意図しないレポート化（情報露出）を防ぐ |
| D-3 | 「著名でないパッケージ」の判定基準 | データ駆動の許可リスト（ルールパック同梱、ユーザー拡張可）＋タイポスクワッティングヒューリスティック（許可リスト名との編集距離・紛らわしい文字置換）。ネットワーク照会は行わない | オフライン・決定性の要件と両立させる。許可リスト外は Low（Info 相当の注意喚起）、タイポ疑いは High とする |
| D-4 | 設定スキーマの更新追従 | パーサとルールパックにスキーマバージョンを持たせ、未知のキーは許容して解析を継続し、Info として報告する。ルールパックはツール本体と独立に更新可能とする | スキーマ変更でツールが壊れず、追従漏れも可視化できる |
| D-5 | LLM による解説生成 | MVP のスコープ外とする。将来導入する場合は、オプトイン・デフォルト無効、マスキング済みデータのみ送信、Amazon Bedrock（学習データ再利用なし）前提、スキャン対象を信頼できない入力として扱うプロンプトインジェクション対策を別 spec で設計する。月額 $1 以上の見込みがある場合は導入前に見積もりを提示する | オフライン・決定性要件と衝突するため、MVP では除外する |
| D-6 | AWS デプロイ・マルチユーザー・認証 | MVP のスコープ外とする。将来 Web 公開する場合は共通 Cognito 基盤と AWS WAF を使用する（別 spec） | MVP は AWS コスト 0 を前提とする |
| D-7 | OWASP 対応づけ | 各ルールに OWASP Top 10 for LLM Applications 2025 のカテゴリ（LLM01 Prompt Injection / LLM02 Sensitive Information Disclosure / LLM03 Supply Chain / LLM06 Excessive Agency 等）を参考情報として付与する | 検出の抜け漏れをカテゴリ単位でレビュー可能にする |
| D-8 | シークレットのマスク形式 | 原文の文字を 1 文字も含めない固定表現（例: `<REDACTED:aws_access_key:len=20>`）とし、部分表示（先頭 4 文字等）やハッシュも出力しない | 部分表示やハッシュは短いシークレットの推測・総当たりの手掛かりになる |
| D-9 | 終了コード | 0 = 閾値以上の検出なし、1 = 閾値以上の検出あり、2 = 実行エラー（引数不正・ルールパック不正・抑制ファイル不正）。閾値のデフォルトは High | CI での扱いを明確にし、ツール自体の失敗と検出を区別する |
| D-10 | 未知の Rule ID の指定（`--disable-rule`・`disabled_rules`・Severity 上書き） | 警告を標準エラー出力に出すのみでスキャンを継続し、終了コードは変えない（Requirement 5.11） | Rule_Pack の更新で Rule が廃止・改名されても既存の CI 設定が即座に壊れないようにする |
| D-11 | Rule ID の重複 | 組み込み Rule_Pack と追加 Rule_Pack の間の重複も含めてエラー（終了コード 2）とする。Severity は Suppression_File の上書き設定でのみ変更可能とする（Requirement 5.5・5.6） | 同名 Rule による暗黙の上書きで検出が弱められることを防ぎ、変更経路を 1 つに限定する |
| D-12 | 正規表現評価のタイムアウト | 線形時間保証のある正規表現エンジンを第一の対策とし、1 評価あたり 100ms のタイムアウトは補助的な安全策とする。タイムアウト発生時は Scan_Error として記録する（Requirement 5.8・5.10） | ReDoS を防ぎつつ、実行環境の速度に依存しない決定的な結果（Requirement 22）を担保する |
